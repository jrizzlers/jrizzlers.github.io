👋 What This Software Does

s6e8-lookup-transformer is a complete, self-contained prediction tool built for the Kaggle S6E8: predicting a binary outcome from a table of numbers and categories. Instead of asking you to install programming languages, configure training scripts, or tune settings by hand, this release packages the whole workflow into one program you can launch with a double-click.

Behind the scenes the application uses a lookup-transformer model — a modern deep learning design that combines a fast lookup step for repeated category values with a transformer layer that learns how different columns relate to each other. In plain terms: it looks at every row of your data, remembers patterns it has seen before, and then weighs which details matter most when making a prediction.

The model in this release scored a public leaderboard ROC AUC of 0.97041 in the original competition, and the approach was adopted as part of a 14th-place solution. 🧭 How to Use the Results

The results file contains one row for every row in your input, in the same order, with the original identifier carried across so you can match predictions back to your source. Predictions appear as values between 0 and 1. A value closer to 1 means the model considers the outcome more likely; a value closer to 0 means the opposite. A value near 0.5 indicates the model found the example genuinely ambiguous.

If you are preparing a submission for a leaderboard, use the identifier column and the prediction column together and leave the other columns out. If you are reviewing results for a business decision, sort the file by the prediction column and look at the highest and lowest scoring rows first — those are the cases where the model is most confident.

Predictions are estimates, not certainties. Treat the scores as a way to rank and prioritise examples, and avoid reading small differences near 0.5 as meaningful.

📝 About the Model

The approach began as a competition experiment and was refined into a dependable default. It treats each row as a short sequence of column tokens, uses a lookup table to represent repeated category values compactly, and applies transformer attention to learn which columns should influence each other. Numeric columns are normalised and blended into the same representation, so the model sees one unified view of your data rather than separate numeric and categorical tracks.

Training used standard augmentation and validation practices appropriate for tabular classification, with careful feature engineering on the categorical fields that dominate this competition. The result is a model that holds up well beyond the examples it was trained on, which is why it also performed strongly when adopted into a larger ensemble that finished 14th.
